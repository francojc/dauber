# v0.1.9 Plan: Quality Baseline + Module Item CRUD

**Project:** dauber
**Status:** complete
**Target:** next maintenance release

## Goal

Turn v0.1.9 into a small, practical release: quantify test coverage, fill the most obvious Canvas modules gap, and prepare for future live integration testing without making Canvas credentials required for normal development.

## Scope

### 1. Coverage baseline

Current state: `pytest-cov` is already listed in dev dependencies, but coverage is not configured, measured, or reported in docs/CI.

Tasks:

- [x] Add coverage configuration to `pyproject.toml`.
- [x] Add/update `just cov` recipe.
- [x] Update CI and developer docs to expose coverage command.
- [x] Run first coverage report and record current percentage in `specs/progress.md`.
- [x] Defer minimum threshold until one baseline release has shipped.

Acceptance criteria:

- `uv run python -m pytest --cov=dauber --cov-report=term-missing tests/` works locally.
- Coverage report excludes tests and generated/irrelevant files.
- Progress spec records measured coverage.

### 2. Module item CRUD

Current state: modules can be listed, shown, created, updated, and deleted; module items can be read through `modules show` but not managed directly.

Tasks:

- [x] Add service functions for Canvas module items:
  - `list_module_items(client, course_id, module_id)`
  - `get_module_item(client, course_id, module_id, item_id)`
  - `create_module_item(client, course_id, module_id, ...)`
  - `update_module_item(client, course_id, module_id, item_id, ...)`
  - `delete_module_item(client, course_id, module_id, item_id)`
- [x] Add CLI commands under `dauber modules items`.
- [x] Support common Canvas item types: Page, Assignment, Discussion, File, ExternalUrl, SubHeader.
- [x] Preserve scriptable output formats.
- [x] Add service and CLI tests with mocked CanvasClient/service calls.

Acceptance criteria:

- Users can add, move/update, inspect, and delete module items from CLI.
- Tests cover happy paths and CanvasError wrapping.
- Existing `modules list|show|create|update|delete` behavior remains unchanged.

### 3. Integration-test scaffold

Current state: live smoke tests have been run manually, but integration tests are not represented as a repeatable, opt-in test layer.

Tasks:

- [x] Create `tests/integration/` with a skipped-by-default pattern.
- [x] Add pytest marker/config for `integration`.
- [x] Document required environment variables (`CANVAS_API_KEY`, `CANVAS_BASE_URL`, `CANVAS_SANDBOX_COURSE_ID`).
- [x] Add one minimal read-only connectivity test that only runs when credentials are present.

Acceptance criteria:

- Normal `pytest tests/` does not require Canvas credentials.
- Integration tests are clearly opt-in.
- Docs explain how to run them safely against a sandbox course.

## Non-goals

- No broad Canvas API expansion beyond module item CRUD.
- No default-on live integration tests in CI.
- No coverage threshold enforcement unless baseline is comfortably high and stable.
- No student workflow commands.

## Test plan

- `uv run ruff check src/ tests/`
- `uv run ruff format --check src/ tests/`
- `uv run python -m pytest tests/`
- `uv run python -m pytest --cov=dauber --cov-report=term-missing tests/`
- Optional: `uv run python -m pytest tests/integration/ -m integration` with sandbox credentials
